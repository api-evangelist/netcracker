# Netcracker

> Netcracker Technology (Waltham, MA; a wholly owned NEC subsidiary) sells BSS/OSS, digital
> commerce and monetization, charging, orchestration and API management software to
> communications service providers. It is a supplier to carriers, not a carrier. Its
> commercial telecom APIs — the TM Forum Open APIs its products implement — are entirely
> partner- and contract-gated: netcracker.com publishes no developer portal, no downloadable
> product specification and no sandbox. Its one genuinely public, self-serve API surface is
> Qubership, the open-source cloud platform at github.com/Netcracker, which ships real
> OpenAPI/Swagger contracts, two MCP servers, client libraries and agent skills under
> Apache-2.0. Generated by API Evangelist (apievangelist.com) from the netcracker company
> repo; provenance for every claim is in review.yml.

## APIs (public, open source — self-hosted)

- [Qubership APIHUB Registry API](https://netcracker.github.io/apihub/): OpenAPI 3.0.3, 111 paths — API registry and developer portal: packages, versions, revisions, documents, operations, publication, change classification, operation groups, search, DDL and MCP contract catalog, AI chat.
- [Qubership APIHUB System Administrators API](https://netcracker.github.io/apihub/): OpenAPI 3.0.3, 18 paths — package transitions, system operations, role and administrator management.
- [Qubership MaaS API](https://github.com/Netcracker/qubership-maas): Swagger 2.0, 35 paths — provisions Kafka topics and RabbitMQ virtual hosts for microservices. HTTP Basic auth.
- [Qubership DBaaS Aggregator API](https://github.com/Netcracker/qubership-dbaas): OpenAPI 3.1.0, 73 paths — Database-as-a-Service aggregator; databases, users, backup/restore, balancing rules, physical database registration. Bearer JWT.

## Agents and MCP

- [MCP servers](https://raw.githubusercontent.com/api-evangelist/netcracker/refs/heads/main/mcp/netcracker-mcp.yml): apihub-mcp (streamable HTTP at `https://{apihub-host}/api/v1/mcp/`, 7 tools, 1 dynamic resource, 1 prompt, auth required) and apihub-api-diff (local stdio, 1 tool).
- [Tool crosswalk](https://raw.githubusercontent.com/api-evangelist/netcracker/refs/heads/main/mcp/netcracker-tool-crosswalk.yml): each MCP tool bound to the REST operationId that backs it.
- [Agent skills](https://raw.githubusercontent.com/api-evangelist/netcracker/refs/heads/main/skills/_index.yml): Netcracker publishes first-party SKILL.md agent packages across the Qubership org (an `apm.yml`/`agent-packages/` convention targeting Cursor and Claude), plus AGENTS.md in 22 repositories.
- [Agentic access profile](https://raw.githubusercontent.com/api-evangelist/netcracker/refs/heads/main/agentic-access/netcracker-agentic-access.yml): recommended x-agentic-access contracts for 276 operations.

## Operating contract

- [Authentication](https://raw.githubusercontent.com/api-evangelist/netcracker/refs/heads/main/authentication/netcracker-authentication.yml): bearer JWT, api-key header, X-Personal-Access-Token, apihub-access-token cookie, HTTP Basic. No OAuth 2.0, no OIDC discovery document — SSO is federated to the operator's own IdP.
- [Conventions](https://raw.githubusercontent.com/api-evangelist/netcracker/refs/heads/main/conventions/netcracker-conventions.yml): page/limit pagination (page from 0, limit max 100), submit-then-poll async jobs, SSE only on AI chat, no rate-limit headers, `clientMessageId` idempotency on AI chat sends.
- [Errors](https://raw.githubusercontent.com/api-evangelist/netcracker/refs/heads/main/errors/netcracker-problem-types.yml): vendor `{status, code, message, params, debug}` envelope (not RFC 9457), plus a TM Forum `TmfErrorResponse` shape in DBaaS.
- [Lifecycle](https://raw.githubusercontent.com/api-evangelist/netcracker/refs/heads/main/lifecycle/netcracker-lifecycle.yml): four URI-path API versions in parallel, 16 deprecated operations, releases every 4-6 weeks, no status page and no SLA (self-hosted).
- [Changelog](https://raw.githubusercontent.com/api-evangelist/netcracker/refs/heads/main/changelog/netcracker-changelog.yml): APIHUB 2.5.2 → 2.12.0, dated.
- [Data model](https://raw.githubusercontent.com/api-evangelist/netcracker/refs/heads/main/data-model/netcracker-data-model.yml)
- [Conformance](https://raw.githubusercontent.com/api-evangelist/netcracker/refs/heads/main/conformance/netcracker-conformance.yml)

## What is NOT here

- No developer portal on netcracker.com (developer./developers./docs./api. do not resolve; /developer, /developers, /api return 404).
- No CAMARA implementation. CAMARA is named in product marketing only; no CAMARA API is specified or callable anywhere in the public surface.
- No TM Forum specification, TMF API number or conformance certificate published, despite a claimed TM Forum Platinum badge and Ready for ODA certification.
- No AsyncAPI document of Netcracker's own (APIHUB consumes and renders other teams' AsyncAPI).
- No GraphQL endpoint, no public gRPC service contract, no webhooks, no public Postman workspace, no /.well-known/ discovery document, no status page.
